# Progress tracker

Last updated: 28 Nov 2026.

## How to update this file

- Update at the end of every work session, by people and AI agents alike.
- Change task status in the tasks table; never delete rows.
- Add new entries at the top of each log, newest first.
- Dates in `YYYY-MM-DD`. Keep entries to one or two lines; link PRs instead of explaining them.
- A decision that changes a doc gets a decisions log entry and a doc changes log entry.
- If this file grows past 600 lines, move log entries older than 90 days to a dated section at the bottom called "Archive" in a single summary line per month.

## Status values

| Value | Meaning |
|---|---|
| Not started | No work yet |
| In progress | Someone is working on it now; owner set |
| Blocked | Cannot continue; the Notes column says why and on what |
| In review | PR open |
| Done | Merged, "done when" met, tests passing |
| Moved | Moved to a later phase or release; Notes says where and why |
| Dropped | Removed from scope; decisions log says why |

## Notes for later

- Compose 1.13 (compose-bom 2026.11.01, Dependabot #211): left out on purpose and #211 closed on 2026-11-28 by Blair's choice. It needs compileSdk 37.1 or later (only the 37.0 platform is installed; `platforms;android-37.1` is available from sdkmanager) and a migration of `HueSlider` in `appearance/AppearancePicker.kt` to the new `Slider` track API. Do it in its own pull request with an emulator check of the whole app.
- P1-10 left out the "Base URL" field of the provider detail prototype (`set-provider-detail`). The `provider_configs` table already has a `base_url` column and every adapter config takes a base URL, so adding the field later is a screen change plus passing the saved value into `check_provider` and the adapters. Decide whether a proxy is in scope before P1-11.
- The biometric check before showing a saved key is a screen gate, not a cryptographic one: the Keystore key that wraps secrets needs no user authentication, so background turns can call providers (see mobile.md). A later task may bind the reveal to the Keystore if that is wanted.
- P1-11 (event pipeline) owns three gaps found in the P1-01 review: Kotlin needs a way to read the session id of any `CoreEventView` without a per-variant `when` (add `CoreEvent::session_id()` in the engine and expose it); `EventBus` replays 16 events and drops the oldest of any kind, but architecture section 4 says only `TextDelta` drops, and `ApprovalRequired` and `TurnFinished` must not drop; and the 400-line file limit will need `views/event.rs` split by event group once about 10 more events land.
- P1-02 defined the text forms of `Role`, `SessionStatus`, `PermissionMode`, `Provider`, and `ConnectionStatus`. The text forms of `Executor` and `ToolCallStatus` arrive with the tables that store them. P1-11 decides what to do with an unknown part kind in `body_json`.
- P1-11 sizes the store for the session actor: `Store` owns one connection (`Send`, not `Sync`), `Store::open` cannot serve read connections, and sessions have no stop-reason, archive, or context-size column yet. Add them in a numbered migration when the turn loop needs them.
- P1-15 adds `message_fts` with triggers or cleanup, because `ON DELETE CASCADE` does not reach a virtual table.
- P1-09 maps a catalog context window of 0 to NULL, because the schema rejects 0.
- When `Store::open` is wired into the core, add a guard for a development database whose 0001 was edited after it was created.
- `ToolProposed` and `ApprovalRequired` carry only the tool and the target. The approval bar will also need the executor and the rule text for "Always allow"; add the fields in the task that builds that bar.
- Reasoning replay: Anthropic thinking signatures, Gemini thought signatures, and OpenAI reasoning items are all dropped today, so a tool loop on a model that requires them can fail (Anthropic and OpenAI are worked around; Gemini has no documented bypass). Fixing it needs `MessagePart::Thinking` to carry opaque provider data and the store to keep it. Decide before the tool phase (P2).
- Google calls `generateContent` legacy and recommends its Interactions API. Revisit the Gemini endpoint when that API is stable.
- Consider sub-agents for read-only exploration early in v1.1; the turn engine should not assume one agent per session.
- Scheduled tasks (v1.2) should only run while charging and on Wi-Fi by default.
- Watch for a stable Node-compatible WASI runtime; it would move many JavaScript tasks from Linux mode into the sandbox.
- Revisit local model inference when mid-range phones can run a useful coding model at interactive speed.
- Telegram and Discord connectors only work while the phone runs Tether's service; say so plainly in their setup screens.
- Whether to fork or reuse parts of an open-source harness (Codex CLI, Goose) is not decided. A spike that cross-compiles their core crates for Android would settle it before P2.
- The Android vector logo was traced by hand from a 287 px raster. Replace `images/logo.svg` with the original vector when one exists, then update the two launcher drawables.
